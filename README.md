# MementoMori 配队构筑器

供玩家配置五人队伍、查看资源等价钻石并导出 JSON 构筑方案的静态网站。浏览器自动保存草稿；文件通过玩家自己的联系方式发给构建方。无登录、自动上传、游戏请求或后台服务。

## 使用与发布

Node.js 24：`npm ci`、`npm test`、`npm run build`。本地开发使用 `npm run dev`，地址为 `http://127.0.0.1:5840/`。提交 main 后，GitHub Actions 自动构建并部署到 GitHub Pages；相对资源路径支持项目子目录。

全站文字与数字使用Noto Sans SC／Microsoft YaHei。Georgia（含Pro、派生、回退与嵌入）、MS Gothic及ＭＳ ゴシック均禁止使用。`npm run build`在构建前检查源码、构建后检查发布文件，命中禁用字体即失败；`npm run check:fonts`可单独检查。此规则同样适用于恢复旧版本。

本机还安装了独立于仓库版本的推送前检查，直接检查待推送提交；恢复旧源码不会删除这道门禁。该本机门禁仅保护已安装它的开发环境，GitHub Pages部署同时通过构建检查验证发布文件。

本次构筑采用“诅咒·时之枷锁”：所有角色等级固定为450级。只列初始SR角色，可选择SR/LR/LR5；LR装备要求LR5，SSR专武最高240级。UR／LR武器只提供专武，不提供无法取得的通用武器。防具分为SSR撒旦、UR米迦勒、LR梅塔特隆。六槽各有四符石孔，攻击与防御符石依实际槽位限制，同一件装备不重复类别。穿透与速度允许1–15级；其余类别整队每类提供3颗11级和3颗10级，两档库存独立，不能额外购买。秘仪按持有角色的实际LR／LR5档位自动解锁并汇总加成；角色属性页按450级、玩家等级560的静态构筑计算，包含当前装备、强化、符石、圣魔装及已解锁秘仪，不计战斗技能与临时增益。

新加入的角色优先装备自己享有的免费专武，否则借用尚未被其它队员使用的同职业免费UR专武，没有可借武器时预置自己的SSR180专武。专武归属独立保存：借用须同职业，同一把赠送专武只能装备给一名队员；实际装备到450级时才纳入自动制作优惠的计数，借用其它角色的专武不启用自己的专武技能。旧草稿保留原配置，可在编辑器内调整。

“我的配队”位于中间“02 角色与装备”顶部右侧，与当前角色信息并排，窄屏上下排列。队伍沿用5811前端五个台座位的布局，不显示角色名字，展示头像稀有度边框、等级、六部位装备档位和实际魔装等级。可拖动整名队员交换位置，也可把左侧目录角色拖入指定位置以加入或替换，保留该位置的稀有度、装备、强化及符石设置，按新角色重新计价；拖回角色目录即可移出队伍。队伍卡片不提供箭头或删除按钮，点击队员用于编辑装备。角色目录名称与副标题各固定一行，缺少副标题也保留行高，避免SP标识造成卡片错位。头像角标使用六种原版属性图标，不以“水／火／风／土”等文字替代。中间区域直接编辑当前角色的六部位装备，右侧显示费用与免费抵扣。

新装备魔装默认40级；已有草稿与导入文件的等级不会被覆盖，移除装备清空魔装及其它养成。SSR／UR／LR档位提供原版装备图标便于切换，LR仍需LR5角色。符石四孔横排四列，每列上方选择类别、下方显示并调整等级，原有孔位、库存和类别限制不变。

装备按固定两列排列：左侧武器、项链、手套，右侧头盔、衣服、脚。窄屏依次排列左组、右组，六槽身份与导出顺序保持不变。

提供四件套、2UR、2LR、6LR快捷配装：四件套对SR／LR角色使用4UR，对LR5使用4LR；两件高阶为武器和项链，四件再加头盔和衣服，其余为SSR；6LR全部采用LR。独立LR方案要求角色LR5，不自动升级角色。沿用原方案的制作等级：高阶项链、头盔和衣服240，武器、手套、脚450，普通SSR450。强化为武器／手套／脚450、头盔／衣服240、项链60，并受装备等级上限约束。保留已装圣魔等级、符石与专武归属，新装备魔装默认40。LR5降至LR时所有LR装备自动转为UR，保留原等级与养成并按新配置计费；升回LR5不自动把UR装备升级。

圣装、魔装等级旁展示当前部位对应的词条加成；按真实主表的非线性等级曲线取值，不用等级乘固定比例。圣装百分比显示其属性比例，魔装显示固定值，不把该预览描述成已计算角色最终战力。

“角色属性”页展示主要属性、四维和进阶属性，并可展开来源。角色等级450、副等级0，玩家等级560；包含基础成长、当前稀有度、装备／强化、符石、圣魔装、自身专武固有词条、套装与已解锁秘仪。借用专武不获得归属角色的固有词条，不计战斗技能、临时增益或战斗阵营加成，不展示推测战力。每件装备默认主属性满打磨：游戏单属性上限60%，余40%均分；选择“四维均分”则各25%，整数尾差按力量／战技／魔力／耐力固定顺序分配。打磨选项随构筑保存、导入；旧方案默认主属性且不新增打磨费用。

首次向某装备空孔安装符石时，自动将同列另外两个已装备部位的同序号空孔填为相同类别与初始等级。已有符石不覆盖，同件已有同类则跳过；自动填充遵守普通符石整队每类每级库存，后续各孔微调独立。

队伍概览的装备图标沿用5811的底板、前景、原版稀有度框三层合成。底板为灰色、圣装橙色、魔装紫色或双圣魔青色，显示实际装备的养成状态，前景不会被染色。

中间面板提供“配队与装备／秘仪／角色属性”页签，首页标题标注“身为剑所天成 · 简易杯初筛”。秘仪购买只补齐所需LR角色：已在配队、其它已购秘仪或免费库中持有的角色共同计价，同一角色仅按最高所需稀有度收一次本体费用。购买时配队内对应SR提升为LR，已有LR5保留；获得的队外LR角色仍可拖入五人队伍。取消购买移除该秘仪的购买需求，队伍中已有的稀有度保持不变并重新计算费用。

常驻四色免费LR5、常驻光暗免费LR直接参与解锁条件，不另赠超出持有条件的档位。秘仪所需R角色免费持有LR，仅用于秘仪条件，不加入SR配队目录。含0号占位的秘仪显示尚未开放，不能购买。每组按实际持有选择LR或LR5的一档属性，不叠加低档；页面汇总已生效加成，战斗系统接入仍为后续工作。

恩泽“绯红”提供整队全部免费红水额度88,888，基础额度为0，不叠加旧版6万基础或4万恩泽。`allowances`记录基础，`blessings`独立记录恩泽；共用计算模块在显示、计费及导出时统一求和。移除该恩泽后当前规则没有免费红水；旧版没有恩泽字段的策略可继续按其原额度计算，旧方案导入则按当前88,888总额度重算。

恩泽“锻造”仅免普通SSR装备的制作碎片费用，SSR专武沿用专武定价、免费库及紫晶预算。原投入碎片数量、参考单价保留，恩泽抵扣在费用细目另列，不与免费库重复抵扣，也不免强化、符石、圣装的超额费用；升级UR／LR不会继承普通SSR制作豁免。此恩泽以`effect:freeEquipmentCrafting`明确记录，资源额度恩泽仍兼容原来的`resource`与`amount`字段。

恩泽“生命”提供整队60,000钻叶子预算，按钻石扣除、不兑换成取整叶子数量。“紫晶恩泽”提供每把专武UR240的制作基线（275片＝82.5紫水晶），替代旧8万钻共享紫晶池；更高等级只计算基线以上差额。先应用第3／6把武器300级制作优惠，再与免费库基线取最大权益，不相加重复抵扣，免费UR300赠品原有权益保留。紫晶基线只免专武制作，不免叶子、强化、符石或圣装；原参考单价与投入数量仍保留。普通装备圣遗物按50碎片＝2材料折算。LR装备碎片成本只汇总配队中LR普通装备的圣遗物碎片投入与实际钻石，不展示逐件明细，不混入UR碎片、专武紫水晶或叶子；该费用已计入全队总额。每名队员实际投入包含本体及该队员全部装备养成，已包含在全队总额中；秘仪队外角色单独列出，避免重复计费。

圣装与魔装按累计经验计量：0级为0，L≥1为 `1+L×(L−1)/2`；40级=781。不会把四件10级当作一件40级。符石穿透与速度每颗L级为 `2^L` 饼干；其它类别按各自固定库存计数，不能兑换成穿透或速度，也不折算为未鉴定符石收费。最终钻石总额保留两位小数。

普通UR防具通过UR碎片直接制造，普通LR防具另需50叶子；UR专武累计15叶子，LR专武累计65叶子。SSR普通450级累计655片，UR/LR普通防具450级650片，UR/LR专武450级950片。强化450级每武器8418红水，其它每件4209红水。

专武明细列出紫水晶等价、免费抵扣、叶子和应付钻石。10片专武碎片等价3颗紫水晶；显示等价数量，不把碎片尾数向上凑成整批购买。当前每颗紫水晶等价153.5589430894钻，与专武碎片单价保持相同计费口径。

## 共用免费库与简称

[`public/data/free-library.json`](public/data/free-library.json) 明确保存免费权益：20名常驻四色角色至LR5、2名常驻光暗角色至LR，以及穆瓦诺（管家／穆诺瓦）、希维、圣妹、香蕉、绿狼、夏姆、灾芽、小白、厄瑞涅（教官）、露莎卡（天泣）十名指定角色的SR本体。升到免费档位以上只计累计本体差额。

绿狼、夏姆、灾芽、露娜琳德和教官享有UR240专武；科迪与佛罗伦斯享有UR300专武，均包含15叶子免费。香蕉、圣妹、管家、芬里尔（水狼）和梅琳（梅林）享有SSR180专武。装备到更高档位时只抵扣已授予的免费基线；UR专武升LR另需50叶子、20,000钻，普通LR装备每件50叶子、20,000钻。强化、符石、圣装分别使用既有整队额度。

武器同步自动计价，不再提供同步位和队外基准编辑。按配队位置依次统计实际450级的UR／LR专武，第3把及第6把按300级制作材料计价，第4／5把仍按450级；实际等级和强化上限保持450，叶子与稀有度进化费用正常计算，再扣免费库。当前五人配队最多触发第3把优惠，第6把规则保留供后续5830扩展。免费UR300专武不冒充450级武器。旧同步方案迁移时根据合法旧基准计算真实有效等级，保留装备实际等级后清理同步位与队外基准，并按新规则重算；无法核实的旧同步配置不会采用文件自报费用或有效等级。

[`public/data/name-aliases.json`](public/data/name-aliases.json) 保存正式角色／道具身份及简称，网站搜索支持角色简称。道具简称包括叶子、饼干、红水、绿水、绿球及红球；绿水是强化水，绿球是经验珠，红球是潜能宝珠。日后明确约定的新简称直接追加到这个库，保留正式身份。

5830通过只读资源策略接口读取上述同一份文件，提供免费本体和专武抵扣预览。该接口不修改已有玩家档案；完整配队文件转账号仍按下节规划接入。

## 配队文件与未来5830接入

导出格式 `mementomori-team-plan`，`schemaVersion:1`，保存目录版本、五人顺序、全部装备/符石参数、已购买秘仪编号`purchasedArcanaIds`、当前计价策略、免费库完整快照及费用明细，包括自动同步的实际等级与制作计费等级。此文件是构筑计划，不是游戏账号快照。导入网站只接受已知结构并按本网站当前策略、秘仪目录和免费库重新计价，忽略文件中声称的费用、策略及免费权益。旧文件缺少已购买秘仪字段时按空列表处理；未知、重复或未开放编号拒绝导入。文件没有账号ID、令牌、私有路径或真实玩家数据。

计价纯模块 [`src/domain.mjs`](src/domain.mjs) 与静态属性纯模块 [`src/character-stats.mjs`](src/character-stats.mjs) 不依赖React、网络或私有模拟器，可用同样输入在其它系统调用。5830后续应采用管理员选定的策略重算费用，把计划转换为新模拟账号，并按本机职业、系列、等级解析内部装备和符石ID；秘仪持有及静态角色属性已在本站计算；玩家560级及打磨属性随策略／装备参数记录，实际战斗接入仍由构建方处理。本站不声称已经实现5830导入或计算真实战斗。

## 数据来源

角色名、元素、职业、头像、属性图标、稀有度边框、装备档位图标及队伍背景仅取自已公开的 [`GuangShiX/mmtm-assets-fallback`](https://github.com/GuangShiX/mmtm-assets-fallback)，按公开清单SHA-256验证并随静态站本地提供。`public/data/asset-lock.json` 锁定来源提交、路径、原版Sprite身份与哈希；`node tools/sync-public-catalog.mjs` 是显式维护操作，不在玩家启动时联网更新。仅同步游戏UI资源使用`--ui-only`并沿用现有锁定提交，不刷新角色数据。可通过环境变量 `ASSET_REF` 指定新的已公开提交，`PUBLIC_ASSET_CACHE` 指向该公开仓库本地缓存，缓存必须与清单哈希匹配。

`--display-only`仅更新5811装备合成的尺寸和底板显示元数据，不联网刷新素材；`--arcana-portraits-only`仅同步已锁定公开清单中的12个R角色头像。秘仪目录独立保存为[`public/data/arcana-catalog.json`](public/data/arcana-catalog.json)：仅含100组名称、成员ID、LR／LR5展示加成、R角色公开头像引用和来源哈希。管理员显式运行`tools/sync-arcana-catalog.py <主表快照目录> --snapshot-date YYYY-MM-DD`维护该精简目录，不公开完整主表、私有实现或账号资料。
